### run 55 の絵で見つかったもの（撮影地の突き合わせが対称だった）

撮れた1枚に3件出ていた。**どれも根は1つ**——アプリの `PhotoQuery` が
撮影地を**対称に**突き合わせていた（`a.contains(b) || b.contains(a)`）。
Web は同じ対称版を名指しで捨てている（`lib/utils/related.ts` の
`photoIsInLocation`——「広い場所の写真が狭いページに載る」）。

### run 56 の絵で見つかったもの

- 🔴 **同じ写真に2つの名前**。ホームのカードは `luzhj`、写真の詳細は
  「ユーザー」。詳細が `UserProfile.name`（名前が無いと「ユーザー」を返す
  ＝**nil にならない**）を先に見ていて、写真に添えられた名前まで
  降りてこなかった。順番を `AuthorName` に出した——
  **プロフィールの本当の名前 → 写真の名前 →「ユーザー」**。
  代わりの言葉も2つ（「投稿者」と「ユーザー」）あったので1つにした
- **「14-マイページ」という名前で、ログイン画面を撮っていた。**
  `20-写真の詳細` で一度やった失敗（run 49）と同じ形。出ている画面を
  見て名前に書き分けるようにした

**取り下げ**: 「フランス」と「フランス ヴェルサイユ」の札が同じ表紙に
見えたので重複よけを書いたが、**変異を当てたら1件も落ちなかった**。
よく見ると別の写真（柱頭と列柱）で、直す対象が最初から無かった——
絵を読み違えていた。消した。

向きは `LocationMatch` に出した（集約は `photoIsIn`・回遊は `same`＝
Web の `photoIsInLocation` / `sameLocation` と同じ住み分け）。
変異3つ（向きを対称に戻す・含む関係のふるいを外す・札の枚数を完全一致に戻す）で
それぞれ 5件 / 2件 / 2件が落ちる。

実機の絵で確かめられない2枚については、**見なくても分かる形に寄せた**:

- 画面の中の判断を**純粋な関数として外に出し**、変異させて落ちることまで
  確かめてある（`View` の中は `Shims/` の模型で動かせないため）
- 実機でしか出ない壊れ方には**見張り**を置いてある——配られていない
  `@EnvironmentObject`（起動時に落ちる）・`Form` の地の色（画面が灰色）・
  地図の知らせの回り込み（固まる）・**生の日時**（`2026-09-19T17:46:27`）
- それでも**押した感じ・間・重なりは見ていない**。ログインできる CI が
  あれば塞がる（資格情報が要る）

## 判断待ち（owner に決めてほしいこと）

1. **ストーリーの公開範囲**（モック4-7）。モックは3択だが、2026-09-22 に
   「ストーリーは全員に公開しない」と決めた結果、選択そのものが無くなった。

2. **「1投稿に複数枚」が2通りある。** `extraImages`（1行に複数枚・追加ぶんは
   個別ページを持たない）と `groupId`（行は1枚ずつ・アプリだけが束ねる＝
   検索の面積が減らない）。どちらに寄せるか。
