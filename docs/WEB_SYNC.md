## 考え方: **契約は API、意匠は追う、SEO は追わない**

Web とアプリで共有できるのは3層しかない。**ここだけを見れば足りる。**

| 層 | 追う | 追い方 |
|---|---|---|
| `api-user/**` | **必ず** | 機械で突き合わせる（下） |
| `lib/utils/**` | **必ず** | 表示の規則（題の扱い・日付・座標の丸め）はアプリにも同じ判断が要る |
| `app/components/**` | **だいたい** | 導線・文言・並び。画面の作りは寄せる |
| `app/**`（ページ）・`scripts/**`・`public/sw.js` | **追わない** | SEO・静的書き出し・Service Worker はアプリに相手が無い |

## 手順（1回3分）

```bash
# 1. Web 版を最新にする
git -C ../photo-gallery fetch origin main

# 2. 前回合わせたところから何が変わったかを見る
bash Tools/web-changes.sh ../photo-gallery

# 3. 直したら、突き合わせと検査を通す
bash Tools/verify.sh

# 4. このファイルの「前回合わせたコミット」を進めて commit
```

## 機械で見るもの

### `Tools/check-api-parity.py` — API の食い違い

`api-user/serverless.yml` の口と、アプリのサービス層が叩いているパスを
突き合わせる。**3つを見る**:

1. アプリが叩いているのに、サーバーに無い口 → **落とす**（404 になる）
2. 認証が要る口を未認証で叩いている → **落とす**（401 になる）
3. サーバーにあるのに、アプリが使っていない口 → 未実装の一覧（参考）

2026-09-20 時点: **50 の口のうち 50 を実装**、食い違い 0。

> **これは「形」しか見ない。** 応答の中身（鍵の名前・型）は見ていない。
> 実際、`GET /stories/{id}/viewers` の鍵が `users` ではなく `viewers` だった
> 食い違いは、この道具では見つからず**手で読んで**見つけた。
> 応答の形を変える変更（`lib/server/photos.ts` の `PRIVATE_FIELDS`・
> 各ハンドラの `JSON.stringify`）は、目で追うしかない。

### `Tools/web-changes.sh` — 変更の洗い出し

前回合わせたコミット以降で、上の3層を触った変更だけを並べる。
最後に突き合わせも走らせる。

## 追いにくいところ（分かっていて残している差）

| 何 | なぜ |
|---|---|
| プッシュ通知 | サーバー側（APNs）が無い |
| 動画のストーリー | API は受けるが、アプリは画像のみ |
| SEO まわり一式 | アプリに相手が無い（サイトマップ・集約ページ・構造化データ） |

## 文言を足すとき

**画面に出る文字は必ず2言語ぶん書く。** `L("日本語", "English")` か
`Labels.*` を通す。片方だけだと英語の端末でそこだけ日本語が残る。
`Tools/check-swift-refs.js` が見張っていて、日本語の直書きがあれば落ちる。
