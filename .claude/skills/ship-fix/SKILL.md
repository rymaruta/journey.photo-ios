# 作って出すまでの流れ

## 1. 作る（担当 = Agent、`isolation: worktree`）

指示は短く、**目的・直すもの（ファイル:行）・やらないこと**だけ書き、残りは
「`.claude/skills/ship-fix/SKILL.md` の『担当の決まり』に従う」と書く。

## 2. 確かめる（別の担当、読むだけ）

作った担当とは別の Agent に、`.claude/skills/review/SKILL.md` に従って見させる。
重点（回帰しそうな所・安全・デザインの決まり）だけ足して書く。

## 3. 直す

指摘は「直すべき」は必ず、「直したほうがよい」も原則直す。**作った担当に SendMessage で続きを頼む**
（文脈が残っているので指示が短くて済む）。大きく直したら、同じ確かめ役に SendMessage で見直させる。

## 4. Mac → PR → マージ

- `/mac-check` で緑を確かめる。複数の枝が同じファイルを触るなら**統合ブランチ**にマージコミットでまとめる。
- PR の本文: 概要・変えたもの・確かめたこと（件数・Mac の run 番号）・確かめていないこと。
- iOS は Mac が緑なら PR を作ってマージしてよい（main への merge commit）。
- **photo-gallery の develop・main は `/server-release`**。本番（main）へのマージは owner が押す。

## 5. owner への報告

日本語で短く。結論 → 変えたこと → 確かめたこと → 確かめていないこと → 次。
担当の報告をそのまま貼らない。

---

## 担当の決まり（担当への指示にこの節を読ませる）

- CLAUDE.md を読んで従う。返答・報告・コミットは日本語。
- 既存の仕組みを使い回し、写しを作らない。判断は「YYYY-MM-DD 判断」としてコードに注記。
- 画面を変えるなら先に `/design-check` の手順でデザインの板を読む。読めなければ止めて報告。
- 各直しにテストを付け、**直しを戻すとテストが落ちる**ことを確かめる。
- 手元の確かめは `/verify`。push まで。**PR は作らない・main / develop に merge しない**（頼まれたときだけ）。
- サーバー・DB・AWS・Actions・有料サービスには触らない（頼まれたときだけ）。
- コミットの末尾には、会話で指示された帰属の行を付ける。
- 報告: 変えたもの（ファイル:行）・テスト件数・verify の NG 数・push した sha・確かめていないこと。
