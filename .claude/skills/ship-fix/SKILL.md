# 作って出すまでの流れ

## 1. 作る（担当 = Agent、`isolation: worktree`）

指示は短く、**目的・直すもの（ファイル:行）・やらないこと**だけ書き、残りは
「`.claude/skills/ship-fix/SKILL.md` の『担当の決まり』に従う」と書く。

## 2. 確かめる（別の担当、読むだけ）

作った担当とは別の Agent に、`.claude/skills/review/SKILL.md` に従って見させる。
重点（回帰しそうな所・安全・デザインの決まり）だけ足して書く。

## 3. 直す

指摘は「直すべき」は必ず、「直したほうがよい」も原則直す。**作った担当に SendMessage で続きを頼む**
（文脈が残っているので指示が短くて済む）。大きく直したら、同じ確かめ役に SendMessage で見直させる。

## 4. Mac → PR → マージ

- `/mac-check` で緑を確かめる。複数の枝が同じファイルを触るなら**統合ブランチ**にマージコミットでまとめる。
- 🔴 **マージは PR の検証の「Xcode のビルドとテスト」が緑（か skipped）を見てから。** 枝の確認を
  `screens` で絞った回は「Mac でテスト済み」と数えないので、PR の検証が全部を回す（約50分）。
- PR の本文: 概要・変えたもの・確かめたこと（件数・Mac の run 番号）・確かめていないこと。
- iOS は Mac が緑なら PR を作ってマージしてよい（main への merge commit）。
- **photo-gallery の develop・main は `/server-release`**。本番（main）へのマージもこちらで押す（2026-10-30 owner）。

## 5. owner への報告

日本語で短く。結論 → 変えたこと → 確かめたこと → 確かめていないこと → 次。
担当の報告をそのまま貼らない。

## 担当の決まり（担当への指示にこの節を読ませる）

- CLAUDE.md を読んで従う。返答・報告・コミットは日本語。
- 既存の仕組みを使い回し、写しを作らない。判断は「YYYY-MM-DD 判断」としてコードに注記。
- CLAUDE.md「コードを綺麗に保つ」に従い、触った所を前より綺麗にして終える（使わなくなったコードはその場で消す、注記を実装と合わせる）。
- 画面を変えるなら先に `/design-check` の手順でデザインの板を読む。読めなければ止めて報告。
- 画面・操作を変えるなら、`.claude/skills/review/SKILL.md` の「人間工学の観点」の「必ず」10項目を自分でも見てから出す。
- **コードを読んで直し、Mac は確かめに1回（CLAUDE.md・2026-11-19 owner）。** 今ある記録とコードから怪しい所を直し、
  報告に根拠（コードの行と使った数字）を書く。2回続けて外れたら、値を出す仕組みを足して数字を取ってから直す。
- 各直しにテストを付け、**直しを戻すとテストが落ちる**ことを確かめる。
- **Mac は確かめのために流す。直ったか試すために流さない**（2026-11-18 owner「テスト落ちすぎ」・その日 40 回中 24 回落ちた）。
  流す前に `/verify` と手元の単体テストを通す。
- **Mac のテストの前に、必ずビルドだけの回を通す**（コンパイルだけ・テストなし・十数分）:
  `gh api -X POST repos/rymaruta/journey.photo-ios/actions/workflows/ios-testflight.yml/dispatches -f ref=<枝> -f 'inputs[screens]=build'`
  → `bash Tools/wait-mac-run.sh <sha7> build`（run_in_background）。落ちたら job の要約のエラーの行を読んで直す。
- **同じ枝でテストの回が2回続けて落ちたら、3回目を流さない。** 落ちた値（テスト名・期待と実際）とログの行を添えて報告する。
- Mac の確認（`/mac-check`）は**変えた画面の絵だけ撮る**（`inputs[screens]=<画面の名前の一部>`・
  絵の要らない直しは `none`）。全部は main に入る前に PR の検証が回す。
- 手元の確かめは `/verify`。push まで。**PR は作らない・main / develop に merge しない**（頼まれたときだけ）。
- サーバー・DB・AWS・Actions・有料サービスには触らない（頼まれたときだけ）。
- **owner のメールアドレス・個人の情報を外へ送らない**（User-Agent・問い合わせの欄・ログ・コミットにも入れない）。外のサイトから取るときの名乗りは `journey-photo.com` のサイトの URL だけにする（2026-10-31、担当が Commons への要求の User-Agent にメールを入れて1回送った）。
- **共有の作業ツリー（`/home/user/photo-gallery` など）は1人ずつ使う。** 使う前に `git status` と動いている処理を確かめ、ほかの担当が使っていれば自分の worktree で流す。`pkill` のように名前で止めるコマンドは使わず、自分が起動した処理だけを pid で止める（2026-10-31、別の担当の verify を壊した）。
- コミットの末尾には、会話で指示された帰属の行を付ける。
- 報告: 変えたもの（ファイル:行）・テスト件数・verify の NG 数・push した sha・確かめていないこと。
